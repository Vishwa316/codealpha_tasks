Container Lifecycle Explained

1

Created State

Created using docker create. Filesystem structure is established, but the process does not execute yet.

2

Running State

Launched using docker start or docker run. The main process (PID 1) executes, and ports/volumes are actively bound.

3

Paused State

Suspended using docker pause. All processes in the container are frozen (using the cgroups freezer) until resumed.

4

Stopped State

Terminated using docker stop (SIGTERM, followed by SIGKILL if unresponsive). The container process exits, but state files remain.

Docker Deployment Best Practices

  • Use Multi-Stage Builds

    Keeps final images lightweight by separating build environments (e.g. compilers, source files) from production runtime.

  • Run as Non-Root User

    By default, Docker processes run as root inside the container. Explicitly define a non-root user for security isolation.

  • Keep Images Slim (Alpine Nginx)

    Use minimal base images (like Alpine Linux) to drastically reduce the security attack surface and build size.

  • Define Healthchecks

    Configure Nginx health checks in Docker so orchestration tools (like Kubernetes or Docker Compose) know when a container is unhealthy.
